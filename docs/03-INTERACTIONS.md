# Interaction specification

Written before implementation. The test status of each feature is recorded in `TEST-REPORT.md`.

| Feature | Visitor benefit | Trigger → response | Assets / data | Mobile | Keyboard | Reduced motion | Fallback | Scope |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **Garment Explorer** (signature) | See the real colour, the back print and construction details; judge the cut before buying | Colour swatch → whole photo set swaps to that colourway. Front / Back / Detail / Worn tabs → stage crossfades to that view. Numbered marker → its detail note opens and the matching list item highlights | Product media with alt text naming colour and view ("Black, back view"); `custom.details` metaobjects (label, note, view, x, y); `custom.fit_profile`, `custom.fit_note` | Tap targets ≥ 44 px. Swipe isn't required: tabs and buttons do everything. Details list sits under the image | Swatches are a radio group (arrow keys). Views are tabs (arrow keys, Home/End). | **Variant picker + Add to bag** | Choose colour and size, see availability, buy | Pick size → availability text and button update; sold-out sizes are marked "sold out" in text, not by colour alone. A Fit filter appears once the Search & Discovery app exposes `custom.fit_profile` | "Filter & sort" button opens a full-height dialog | Checkboxes and buttons; focus stays on the control that changed | No grid animation | Without JS: GET form with an Apply button (Shopify handles it) | Production. Locally uses mock filter data |
| **Fit scale** (home + product + fit guide) | Understand the cut in plain words | Choose Cropped / Regular / Boxy / Oversized → explanation and matching products update | `custom.fit_profile` per product | Horizontal buttons that wrap | Radio group (arrow keys) | Instant | All four groups listed | Production |

| **Restock request** | Hear when a sold-out piece is back | Submit → validated → Shopify contact form → success message only when Shopify confirms (`form.posted_successfully?`) | Shopify contact form (sends to the store's email) | Same | Native form; errors are linked to fields | n/a | Visible email address | Production on Shopify. | **Mobile menu** | Navigate on phones | Menu button → dialog with links; `aria-expanded` updates | Shopify menus (`main-menu`) | Full screen | Focus trap, Esc | No slide | Links are in the footer too | Production |

| **Interaction analytics** | Owner learns which tools help shoppers | Explorer, fit, filter, lookbook and restock interactions publish custom events with `Shopify.analytics.publish` | Shopify Customer Events (consent-aware) | Same | Same | Same | Nothing breaks if analytics is blocked | Theme code done. The custom pixel is supplied but **not activated** |

## Considered and not built

- **360° spin** needs 24–36 matched frames per colourway, and none exist. A poor approximation would misrepresent the product, so front/back/detail views are used instead.
- **Scroll-driven garment animation** isn't used because it risks scroll hijacking and needs renders that don't exist.
- **Live chat widget** has no agreed data handling.
